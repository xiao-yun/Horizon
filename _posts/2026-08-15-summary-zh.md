## [RustDesk 现支持 Wayland 真正无人值守远程访问](https://rustdesk.com/blog/unattended-remote-access-wayland/) ⭐️ 7.0/10

RustDesk 宣布新增对 Wayland 环境下真正无人值守远程访问的支持，让用户无需在远程端手动确认即可建立会话，填补了 Linux 远程桌面场景的长期空白。 Wayland 已成为许多主流 Linux 发行版的默认显示协议，但其安全模型限制了屏幕捕获和输入注入，导致无人值守访问困难。RustDesk 的这一支持使系统管理员和普通用户能更安全、方便地管理远程 Linux 主机，也推动了开源远程桌面软件对现代 Linux 桌面的适配。 RustDesk 通过处理 Wayland 下的屏幕捕获和输入注入限制实现了无人值守会话，但社区评论指出，自托管场景中的连接仍可能未加密（参见 GitHub issue #3714），使用时需注意安全配置。

hackernews · rustdesk · Aug 14, 16:12 · [社区讨论](https://news.ycombinator.com/item?id=49300759)

**背景**: Wayland 是 Linux 上替代传统 X11 的较新显示服务器协议，默认启用于 Fedora、Ubuntu 等发行版，但由于安全设计，远程桌面软件不能像在 X11 下那样直接抓取屏幕或注入输入。无人值守访问指无需远程端用户在场确认即可建立远程控制连接，通常用于管理服务器或无人设备。RustDesk 是一款开源、可自托管服务器的跨平台远程桌面软件，此前在 Wayland 下的无人值守支持一直受限。

该 GitHub issue（#13153）指出 Apache Iceberg 当前将列统计信息存储为“字段 ID 到值”的映射，在列数增多和新类型加入时导致存储效率低下、内存开销大、无法按需投影特定统计项（如仅取某列的 null_value_counts）以及类型擦除等问题，并提议改进存储模型。 列统计信息是查询优化器制定高效执行计划的关键，优化其存储结构可显著提升大规模分析表的规划与处理性能，尤其影响 Spark、Trino 等引擎在大表上的查询效率。 当前实现采用 map 结构存储各列的下界/上界、值计数、空值计数、大小等统计信息，提案旨在支持按列或按统计项进行投影，降低内存占用并保留原始类型信息。

github · nastra · Aug 12, 22:56

**背景**: Apache Iceberg 是一种开源高性能表格式，用于管理数据湖中的大规模分析表，支持 Spark、Trino、Flink 等引擎并发读写同一张表。查询优化器依赖列统计信息（如最小值/最大值、空值计数、数据大小）来估算代价并生成更优查询计划；投影下推则指只读取查询实际需要的字段或统计信息，避免扫描或加载不必要的数据。本 issue 正是针对 Iceberg 内部列统计存储层的低效问题提出改进建议。

## [Apache Iceberg 提出支持派生列的规范变更（RFC #15923）](https://github.com/apache/iceberg/issues/15923) ⭐️ 7.0/10

Apache Iceberg 社区在 GitHub issue #15923 中提交了一份 RFC，提议修改规范以支持派生列（derived column），具体细节见所附 Google 文档；该提案勾选了“Table”和“Other”作为涉及范围。 Apache Iceberg 是广泛采用的开放表格式，支持 Spark、Trino、Flink 等多种引擎；如果派生列成为规范的一部分，用户可能能够定义由其他列计算得到的虚拟列或计算列，从而简化数据管道、减少冗余存储并提升查询一致性。 此次 issue 本身提供的信息很少，主要链接到 Google Docs 提案文档；从规范勾选看，变更只涉及 Table 和 Other 方面，不涉及 View、REST、Puffin 或 Encryption，但尚未披露具体实现方式或兼容性影响。

github · ScrapCodes · Aug 10, 12:22

## [Apache Iceberg 提议在 v4 规范中新增 varchar 和 char 类型](https://github.com/apache/iceberg/pull/16829) ⭐️ 7.0/10

第 16829 号 PR 提议在 Apache Iceberg v4 规范中新增 varchar(N) 和 char(N) 两种原始类型，以提升与传统 SQL 引擎的兼容性。Spark 自 3.1.0 起已支持 VarcharType(length) 和 CharType(length)，Trino 也原生支持 varchar(n) 和 char(n)。 这一规范变更将提升 Iceberg 与传统 SQL 引擎及主要查询引擎之间的类型互操作性，降低数据迁移和混合查询时的类型转换成本，对广泛采用的数据湖仓生态有积极影响。 该提案目前只涉及 varchar(N) 和 char(N) 两种带长度参数的类型，并未包含传统 SQL 引擎中的 nchar 和 nvarchar。这些类型将作为 Iceberg v4 规范新增的原始类型，具体存储和统计字段的适配还需等待规范定稿。

github · ebyhr · Jul 16, 20:57

**背景**: Apache Iceberg 是一种高性能开源表格式，用于管理大规模分析表，允许多个引擎（如 Spark、Trino、Flink、Presto）并发安全地读写同一张表。Iceberg 规范定义了表结构、数据类型和文件格式等标准，v4 版本目前仍处于提案阶段。传统 SQL 数据库通常提供定长 char(n) 和可变长 varchar(n) 字符串类型；在 Iceberg 表格式中新增这些类型，有助于下游引擎直接映射原生类型，减少类型转换。

## [Apache Iceberg 提议支持默认值表达式](https://github.com/apache/iceberg/issues/17616) ⭐️ 6.0/10

Apache Iceberg 社区在 GitHub issue #17616 中提出了一项提案，将默认值支持从静态常量扩展为可包含值表达式（如函数调用），并配套提供规范 PR #16777 和设计文档。 该改进将使 Iceberg 表的列默认值能够动态计算，减少 ETL 管道中的显式处理，提升数据工程效率，并增强与 SQL 标准的兼容性。 该提案主要针对表规范（Table），已勾选，而视图、REST 接口等暂未覆盖；具体表达式范围可参考关联的讨论邮件和规范 PR #16777。

github · danielcweeks · Aug 12, 14:59
