## [嵌入式工程师回应 RISC-V 批评，强调成本与可及性优势](https://rvembedded.com/blog_post/12/) ⭐️ 8.0/10

一位来自发展中国家的嵌入式工程师发表博文，回应批评 RISC-V 的文章《RISC-V They Should Have Known Better》，强调尽管国际运费高昂，RISC-V 在嵌入式系统中仍具备低芯片成本和可及性优势。 该回应为 RISC-V 生态讨论补充了非欧美视角，说明免许可费、可定制的开源指令集对预算有限的地区具有吸引力，有助于更全面评估其在全球嵌入式市场的发展潜力。 文中提到作者购买 1 美元芯片需支付 60 至 200 美元运费，却称 RISC-V 芯片能以每颗 10 美分到达；评论区有人指出运费远超芯片差价时该优势可能被高估。原文批评主要针对 RISC-V 在嵌入式之外的可选扩展碎片化和性能落后于 ARM64，而本文聚焦嵌入式定制场景。

## [Firefox iOS 版加入原生广告拦截功能](https://support.mozilla.org/en-US/kb/block-ads-firefox-ios) ⭐️ 7.0/10

Apache Iceberg 提出了 issue #15336，建议在 CDC 场景中引入 checkpoint 作用域的去重缓存，以跳过冗余的等值删除操作。当前 Flink CDC 处理 UPDATE 时会生成 DELETE+INSERT，由于逐条处理且缺少批量去重机会，同一 checkpoint 内同一行键往往被多次删除，导致删除记录数比实际需要多 5-10 倍，并产生大量小删除文件，增加 NameNode RPC 压力。 该优化若能实现，可显著减少 Flink CDC + Iceberg 工作负载中的冗余删除文件和 HDFS NameNode 压力，提升 Merge-on-Read 查询性能，降低存储与运维成本，对使用冰山数据湖进行实时 CDC 入湖的数据工程团队有直接价值。 该提案目前只是一个 Issue，还没有实现代码；具体做法是添加 checkpoint 作用域的去重缓存，在单个 checkpoint 内跳过相同行键的冗余等值删除。Flink 逐条处理记录，没有天然的批量去重机会，这是去重缓存要解决的问题。

github · wangyum · Aug 16, 00:11

**背景**: Apache Iceberg 是一种开放表格式，支持行级删除；其中等值删除（equality delete）通过记录被删除行的列值来标识行，常用于按主键的 CDC 和 GDPR 删除，适合 Merge-on-Read 模式。Flink CDC 是一套基于 Apache Flink 的变更数据捕获工具，以 YAML 定义管道，支持 exactly-once 语义，能把数据库变更同步到 Iceberg。在 CDC 中，UPDATE 通常被拆分为 DELETE + INSERT，Flink 逐条处理记录，因此在同一 checkpoint 内可能对同一主键重复产生删除操作。
