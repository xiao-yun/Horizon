## [Cloudflare 优化 1.1.1.1 DNS 缓存节省 100 TB 内存](https://blog.cloudflare.com/dns-cache-memory-optimization-1111/) ⭐️ 8.0/10

Cloudflare 通过仔细优化其 1.1.1.1 DNS 缓存的数据结构和内存分配，将内存使用量减少了 100 TB。该成果涉及递归解析器缓存条目的存储方式调整，显著降低了大规模基础设施的内存开销。 这一优化展示了系统级工程在云服务成本控制中的价值：对全球数百万查询提供服务的 DNS 解析器而言，100 TB 的内存节省意味着可观的硬件成本和能源消耗降低，也反映出基础设施性能调优仍具有重要现实意义。 据报道，优化重点在于消除缓存条目在数据结构和分配中的冗余，而非改变 DNS 解析逻辑。公开摘要未披露具体代码改动，但类似优化通常涉及结构体字段对齐、避免零散分配以及压缩键值存储等技巧。

hackernews · TangerineDream · Aug 27, 17:17 · [社区讨论](https://news.ycombinator.com/item?id=49468083)

**背景**: 1.1.1.1 是 Cloudflare 与 APNIC 合作推出的免费公共 DNS 服务，于 2018 年 4 月 1 日公布，作为递归解析器为互联网用户提供域名解析。DNS 缓存用于暂时保存已解析的域名和 IP 地址映射，以加快后续查询速度并减少对上游权威服务器的请求。Cloudflare 的解析器在全球范围内处理海量查询，其缓存数据量巨大，因此内存优化能带来显著收益。

## [小语言模型已迎来实用化拐点](https://calv.info/small-models-have-arrived) ⭐️ 8.0/10

一篇发表于 calv.info 的文章探讨了小语言模型（SLM）在快速、低成本、面向特定领域任务中的采用趋势。该文章在 Hacker News 上获得 531 分、238 条评论，引发关于模型规模、能力与成本之间平衡的热烈讨论。 这表明行业正从一味追求大模型转向更务实的部署策略：小模型可以在消费级硬件上运行，显著降低推理成本和延迟，让更多中小企业和个人开发者能够将 AI 集成到具体场景中。其影响可能加速 AI 应用从演示走向大规模生产。 小语言模型通常指参数少于 400 亿的模型，常见优化手段包括知识蒸馏、剪枝和量化，使其能在个人电脑或智能设备上运行。评论中还提到，有人在 2024 年初使用 7B 本地模型配合 Guidance 库自动生成测试和代码，说明小模型已能处理特定编程任务。

hackernews · tosh · Aug 27, 15:56 · [社区讨论](https://news.ycombinator.com/item?id=49466917)

**背景**: 小语言模型（SLM）是参数规模通常低于 400 亿的人工智能语言模型，可以部署在个人电脑、笔记本或智能设备上。相比之下，大语言模型（LLM）常包含数千亿甚至上万亿参数，训练和托管需要庞大的计算资源，个人难以用单台电脑和 GPU 完成。SLM 通常采用与 LLM 相同的架构，但通过知识蒸馏、剪枝和量化等方法压缩，在能力与成本之间取得平衡。

## [Apache Iceberg #15336：为 Flink CDC 增加检查点级等值删除去重优化](https://github.com/apache/iceberg/issues/15336) ⭐️ 7.0/10

Apache Iceberg 提交了 #15336 提案，计划增加 checkpoint 作用域的去重缓存，以跳过 Flink CDC 场景中冗余的等值删除操作。 该优化可减少 5-10 倍的删除记录和小文件数量，缓解 NameNode RPC 压力，对使用 Flink CDC 写入 Iceberg 的实时数据湖性能有显著提升。 提案指出 Flink 逐条处理 CDC 记录，UPDATE 会生成 DELETE+INSERT，同一主键在一个 checkpoint 内可能被多次删除；采用 checkpoint 作用域的缓存进行去重。但该 issue 仅为提案，尚未提供实现或社区讨论。

github · wangyum · Aug 16, 00:11

**背景**: 等值删除（equality delete）是 Apache Iceberg 中通过列值（通常是主键）标记删除行的一种机制，不需要定位物理文件位置。Flink CDC 是分布式数据集成工具，将数据库变更实时同步到数据湖。CDC 的 UPDATE 事件通常转换为 DELETE+INSERT，若同一主键在检查点内多次变更，会产生重复的等值删除文件。

## [Apache Iceberg 提出字符串列排序规则支持提案](https://github.com/apache/iceberg/issues/17620) ⭐️ 7.0/10

Apache Iceberg 社区在 issue #17620 中提出字符串类型的列级排序规则（collation）支持提案，允许字段携带提供方限定的排序规则（如 icu.en_US-ci），实现大小写不敏感、重音不敏感和区域感知的比较与排序。该提案保持 UTF-8 存储不变，并存储排序规则感知的最小/最大值以保留分区裁剪能力。 目前 Iceberg 字符串仅按 UTF-8 字节比较，缺乏声明排序规则的能力，导致国际化场景下的大小写、重音和区域排序难以实现。该提案若被采纳，将显著提升数据湖分析中的查询正确性、跨引擎一致性以及去重、排序和过滤优化能力，对数据工程生态有重要影响。 该方案仍为提案，尚未实现；存储层不改变 UTF-8 编码，仅改变比较语义。示例排序规则为 icu.en_US-ci，其中 ICU 是 Unicode 国际组件库，ci 表示大小写不敏感；排序规则感知的最小/最大值会写入元数据，确保分区裁剪依然有效。

github · laskoviymishka · Aug 12, 22:56

**背景**: Apache Iceberg 是一种大规模分析表的高性能开源格式，支持 Spark、Trino、Flink 等引擎并发操作同一张表，并提供了隐藏分区、模式演进等特性。排序规则（collation）是数据库系统中用于定义字符串比较和排序顺序的规则集，如大小写不敏感、重音不敏感或按特定区域语言排序；MySQL、PostgreSQL、SQL Server 等传统数据库均支持 collation。Iceberg 目前仅支持按 UTF-8 字节比较字符串，因此无法声明列级排序规则。分区裁剪是优化器根据分区元数据跳过无关数据文件的技术，Iceberg 依赖列级 min/max 等元数据实现高效扫描。

## [Apache Iceberg 提议支持派生列（RFC #15923）](https://github.com/apache/iceberg/issues/15923) ⭐️ 7.0/10

Apache Iceberg 仓库提交了 RFC #15923，提议在 Iceberg 表格式规范中增加“派生列”支持，并附有详细提案文档；该变更已勾选影响“表”规范及其他部分。 如果 RFC 被采纳，用户将能在 Iceberg 表中定义基于其他列计算得到的派生列，有望减少冗余存储、简化查询并确保数据一致性；这对使用 Spark、Trino、Flink 等引擎的数据湖和湖仓一体场景具有实际价值。 该提案目前只勾选了“表”和“其他”两个类别，未涉及视图、REST、Puffin 和加密等模块；具体设计细节需查看所附的 Google Docs 提案文档。

github · ScrapCodes · Aug 10, 12:22

**背景**: Apache Iceberg 是一种开源高性能分析表格式，允许多个计算引擎（如 Spark、Trino、Flink）同时安全访问同一张表，并支持模式演变和隐藏分区等特性。派生列是指由一个或多个已有列通过表达式计算得到的“虚拟列”，通常不额外物理存储，或只缓存计算结果。该 RFC 旨在把派生列能力标准化到 Iceberg 规范中，使不同引擎对派生列的理解保持一致。
