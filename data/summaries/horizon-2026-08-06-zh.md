## [Webhook 困境与 SCROLL 订阅协议方案](https://weli.dev/blog/the-valley-of-webhooks/) ⭐️ 8.0/10

博客文章深入剖析 Webhook 在状态同步中的难题，并提出 SCROLL 订阅协议作为解决方案，随后在社区引发关于它与 cursor pagination 及 Braid-HTTP 的对比讨论。 该协议试图从协议层面解决分布式系统中实时状态同步的可靠性、去重和启动引导问题，若能标准化，可能推动 API 设计从简单推送向可靠同步演进，影响事件驱动架构的未来。 SCROLL 通过 GET 请求附加 Prefer: stream 头部来建立持久订阅连接，与 Braid-HTTP 的 IETF 草案思路类似；社区建议结合低频轮询与轻量“poke”通知可兼顾效率与实时性。

hackernews · weli · Aug 5, 15:22 · [社区讨论](https://news.ycombinator.com/item?id=49184216)

**背景**: Webhook 是一种 HTTP 回调机制，由服务端主动向客户端推送事件通知，常用于第三方集成，但在状态同步时面临去重、签名验证、消费端启动时数据回溯等挑战。Cursor pagination 是一种基于游标的 API 分页技术，通过返回指向下一页的游标避免偏移量分页的一致性问题。Braid-HTTP 是对 HTTP 的扩展，旨在将 HTTP 从状态传输协议转变为状态同步协议，支持增量更新和订阅。

**背景**: Apache Iceberg 是一种开源高性能表格式，用于管理海量分析数据集，支持 Spark、Trino 等多种引擎并发操作。其 REST API 允许客户端与 Iceberg 目录服务交互，LoadTableResponse 是加载表时返回的数据结构。资源级访问控制（如基于 ARN 的 IAM 策略）需要知道表的唯一标识，而服务端可能生成自定义标识符（如 tableId），此前无法通过标准协议获取。

## [什么是 WAL 回压？ClickHouse Managed Postgres 为何需要它？](https://clickhouse.com/blog/wal-backpressure-clickhouse-managed-postgres) ⭐️ 6.0/10

ClickHouse Managed Postgres 实现了基于 WAL 的回压机制，当归档器恢复时自动降低客户端写入速率，防止磁盘空间耗尽。 该机制可避免因归档滞后导致复制槽积压，从而引发磁盘满故障，保障托管 Postgres 服务的稳定性，对使用该服务的用户至关重要。 通过监控 WAL 延迟，在归档器赶不上时对客户端连接施加回压，可能通过 PgBouncer 或直接限制写入，以保护系统在维护或网络中断后平稳恢复。

rss · ClickHouse Blog · Aug 5, 00:00

**背景**: PostgreSQL 的 WAL（预写日志）记录所有更改；复制槽保留 WAL 直到被备库或归档器消费，若归档器过慢则 WAL 堆积占满磁盘。ClickHouse Managed Postgres 是一个与 ClickHouse 集成分析的托管服务，通过归档器将 WAL 移至 ClickHouse。回压是一种流控技术，在消费者滞后时减慢生产者速度。
