## [Qwen 发布 Qwen3.8-Flash-Next：引入 n-gram 嵌入的 176B 开源模型](https://qwen.ai/blog?id=qwen3.8-flash-next) ⭐️ 9.0/10

阿里巴巴 Qwen 团队发布了 Qwen3.8-Flash-Next 基础模型，总参数约 176B（125B 主模型 + 51B n-gram 嵌入），并系统升级了注意力、残差、嵌入和优化四个模块，提升能力同时优化计算效率、模型容量与训练稳定性。有评论提到，该模型训练成本仅为 Qwen3.7-Plus 的 1/9，且综合表现更优。 作为开源前沿模型，Qwen3.8-Flash-Next 的新架构和高效训练方式可能降低大模型研发门槛，并预示 Qwen 4 的方向。其官方生产版本 Qwen3.8-Flash 默认支持 1M 上下文和内置工具，对开发者、企业和本地部署用户有直接影响。 社区成员指出，主模型 125B 参数加 51B n-gram 嵌入共约 176B，每 token 激活 6B 参数，这种设计以更多内存换取更少计算；但 4-bit 量化后能否在 128GB 统一内存中运行仍存疑问。官方称基于它的生产版本 Qwen3.8-Flash 默认具备 1M 上下文长度并内置工具。

hackernews · tosh · Aug 26, 12:52 · [社区讨论](https://news.ycombinator.com/item?id=49448210)

**背景**: n-gram 嵌入是一种将连续子串向量化的表示方法，与 FastText 等将字符 n-gram 嵌入求和作为词向量的思路类似，能捕捉子词和局部语义信息。在大语言模型中引入 n-gram 嵌入作为额外参数，旨在提升表示能力和训练效率。此前 DeepSeek 发表过相关论文，Gemma 模型也采用了轻量版本；此次 Qwen 将其扩展到 176B 规模。

## [Actinide 成为首家生产高丰度低浓缩铀（HALEU）的初创企业](https://www.actinideinc.com/press/actinide-becomes-first-startup-to-ever-enrich-natural-uranium-to-produce-haleu) ⭐️ 8.0/10

Actinide 宣布成为首家将天然铀浓缩为高丰度低浓缩铀（HALEU）的初创企业，采用升级版 calutron（电磁同位素分离器）技术，从天然铀直接生产 HALEU。该公司此前已有富集镱-176 医用同位素产品。 HALEU 是许多先进核反应堆（包括小型模块堆和第四代设计）的关键燃料，但目前全球商业供应严重不足；初创公司以较低成本进入该领域，有望缓解燃料瓶颈、降低先进核能部署门槛，同时引发核扩散与监管方面的讨论。 HALEU 指铀-235 丰度在 5%至 20%之间的浓缩铀；Actinide 使用的 calutron 是 1940 年代电磁同位素分离技术的现代化改造，被评论认为以几十万美元级设备替代了传统大规模浓缩设施，但其分离效率、产能与商业化前景仍需验证。该公司此前的主打产品是富集镱-176，用于生产医用同位素镥-177。

hackernews · dsalzman · Aug 26, 19:23 · [社区讨论](https://news.ycombinator.com/item?id=49454419)

**背景**: 天然铀中铀-235 含量仅约 0.72%，浓缩可提高其比例。低浓缩铀（LEU）指铀-235 低于 20%，其中 5%-20%称为高丰度低浓缩铀（HALEU）。许多先进反应堆设计需要 HALEU 作为燃料，但全球目前商业产能有限。传统浓缩主要采用气体离心法，电磁同位素分离（calutron）早年在曼哈顿计划中使用，后来被离心机取代。

## [Twitter Viewer：无需登录即可查看推特内容](https://twitterwebviewer.com/) ⭐️ 8.0/10

Twitter Viewer（twitterwebviewer.com）是一个新出现的在线工具，让用户无需注册或登录 Twitter/X 账户就能浏览推文、用户主页等内容。该工具在 Hacker News 上引发热议，获得 291 点、147 条评论。 这解决了长期存在的痛点：政府机构和企业常通过 Twitter 发布公告，但未登录用户几乎无法查看，该工具恢复了公开信息的可访问性。它也呼应了人们对大型社交平台封闭化、强制登录和手机验证的广泛不满。 社区指出其 API 接口（如 api.twitterwebviewer.com/api/user/[用户名]）可返回用户数据，但网站本身广告和追踪较多；目前仍依赖 Twitter/X 未公开接口，可能随时被官方封禁。

## [Apache Iceberg 提出表规范相对路径支持以实现零重写搬迁](https://github.com/apache/iceberg/issues/13141) ⭐️ 7.0/10

Apache Iceberg 于 2025 年 5 月 23 日在 issue #13141 中提议在表规范中加入相对路径支持：当前 Iceberg 对文件路径使用绝对 URI，移动表时需重写元数据；新方案旨在实现“零重写搬迁”，并计划让新表默认使用相对路径。 该变更若被采纳，用户在数据湖中移动表时无需重写元数据，将显著简化表管理和可移植性，对依赖 Iceberg 的多引擎（如 Spark、Trino、Flink）和数据湖管理场景有直接影响；同时符合开放表格式追求可移植性的行业趋势。 相对路径定义为不以 URI scheme 开头的路径字符串，使用前必须相对于表的基础位置解析；目前提案仅在 Table 规范勾选，View 和 REST 规范尚未勾选，说明范围仍集中在表元数据。新表默认相对路径被列为主要目标，但细节还需参考提案文档。

github · talatuyarer · Aug 12, 22:56

**背景**: Apache Iceberg 是一种高性能开源表格式，用于大规模分析表，允许 Spark、Trino、Flink 等引擎安全地操作同一张表。Iceberg 通过元数据文件、manifest 清单和快照来追踪数据文件，当前这些路径使用绝对 URI，因此移动表存储位置就需要重写元数据。相对路径支持意味着路径字符串可以省略 URI scheme，在读取时再结合表的基础位置解析，从而避免搬迁时的大量重写。该提案延续了社区对表可移植性的长期关注（如 2020 年的 issue #1617 也曾讨论相对路径）。
