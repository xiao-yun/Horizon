## [QubesOS 漏洞：复制到虚拟机错误报告致 Dom0 任意代码执行](https://www.qubes-os.org/news/2026/08/29/qsb-118/) ⭐️ 8.0/10

QubesOS 发布 QSB-118 安全公告，披露 `qvm-copy-to-vm` 工具的错误报告回传通道存在漏洞，攻击者可通过构造文件使 Dom0 执行任意代码；仅从 Dom0 发起的复制操作受影响，VM 内版本不受影响。 该漏洞破坏了 QubesOS 最核心的隔离边界：Dom0 一旦被攻破，整个系统可被完全控制。它说明即使高度注重安全的操作系统仍可能存在严重缺陷，并引发关于是否应在 Dom0 中进行文件操作及 Qubes 架构安全性的广泛讨论。 漏洞位于 `qvm-copy-to-vm` 的错误报告函数：Dom0 版本使用 `system()` 执行外部命令，而 VM 版本未使用，因此攻击者需要诱导用户从 Dom0 向不可信 qube 复制文件。QSB-118 公告说明该工具使用简化的 qfile 协议，元数据比 tar/cpio 简单，可能被用于触发任意命令执行。

hackernews · vntok · Aug 30, 08:51 · [社区讨论](https://news.ycombinator.com/item?id=49496918)

**背景**: QubesOS 是基于 Xen 虚拟机的安全桌面操作系统，通过将应用隔离在多个称为 qubes 的虚拟机中降低攻击面。Dom0 是管理所有 qubes 的特权域，拥有最高权限，一旦失守即影响整个系统。`qvm-copy-to-vm` 用于将文件从 Dom0 复制到指定 qube，使用 qfile 协议。官方建议用户不要在 Dom0 中进行日常操作或与不可信内容交互。

## [Iceberg Spark 提交时捕获并发出 Parquet footer 聚合指标](https://github.com/apache/iceberg/issues/16675) ⭐️ 6.0/10

Apache Iceberg 的 issue #16675 提议提供一个可选机制，让 Iceberg 在 Spark 写入过程中直接从 Parquet footer 捕获聚合的物理存储指标，并在提交时通过现有事件框架发出，且不将其持久化到表元数据中。 该机制有望增强数据湖的可观测性，让外部系统基于提交时的聚合统计做出更优的表管理与查询优化决策，而无需修改 Iceberg 表元数据；不过目前影响主要集中在 Spark 集成上。 该提案是可选的（opt-in），捕获的指标包括列级别的 value_counts、null_value_counts、nan_value_counts 等，并通过 Iceberg 现有事件框架对外发送；由于不写入表元数据，历史提交不会携带这些额外统计信息。

github · gtrettenero · Jul 13, 16:49

**背景**: Apache Iceberg 是一种高性能开放表格式，用于管理大型分析数据集，支持 Spark、Trino、Flink 等引擎同时安全地操作同一张表。Parquet footer 中存储了每个行组/列的元数据和统计信息，查询引擎可以仅读取这些信息来跳过无关数据或回答聚合查询。Iceberg 的事件框架允许外部服务在表发生某些操作时收到通知，通常用于表生命周期管理或优化决策。本提案旨在利用该框架将写入期间捕获的 Parquet footer 聚合指标在提交时发送出去。

## [Apache Hudi 提案支持分区软删除](https://github.com/apache/hudi/issues/18774) ⭐️ 6.0/10

github · kbuci · May 18, 22:43

**背景**: Apache Hudi 是一个开源数据湖库平台，在数据湖上提供 ACID 事务、高效 upsert/delete 等数据库能力。分区删除通常涉及移除底层存储文件，并同步更新元数据表和索引以保证一致性。软删除是一种先标记删除、延迟物理清理的策略，为用户预留恢复窗口。
