## [通过重放输出从专有 LLM 窃取推理痕迹](https://stolen-thoughts.com/) ⭐️ 8.0/10

一种新技术通过将前沿大型语言模型（LLM）的输出重放到同家族较弱模型，成功恢复出隐藏的推理步骤，暴露出专有 API 的透明度与安全隐患。 该发现引发对专有 LLM 透明度的质疑：用户可能无法获取已付费的完整推理过程，而该方法可轻易恢复隐藏信息。它还可能被恶意利用，威胁模型安全和用户隐私，动摇 LLM 生态的信任基础。 方法利用重放攻击思路，将前沿模型的输出注入安全限制较松的“兄弟”模型并配合越狱技术提取推理痕迹。论文指出 API 摘要可能掩盖实际回答顺序，而该方法能还原原始推导过程。社区也提到通过禁用思维链并给予模型“思考”工具等手段可达成类似效果。

hackernews · quantumgarbage · Aug 11, 13:22 · [社区讨论](https://news.ycombinator.com/item?id=49257876)

**背景**: LLM 在执行复杂推理时常采用思维链（Chain-of-Thought）生成中间步骤，但专有 API 为保护知识产权或防止滥用，常隐藏这些推理痕迹，仅输出结果或简化摘要。重放攻击（Replay Attack）原本是网络安全中的一种攻击方式，攻击者截获并重放数据以欺骗系统。本研究将其应用于模型推理，利用同一厂商“兄弟”模型间的安全差异来恢复隐藏信息。

## [Git-knife：用电子表格界面重写 Git 提交历史](https://github.com/TheRealYT/git-knife) ⭐️ 6.0/10

Git-knife 是一款新发布的开源 CLI 工具，在 Hacker News 上展示，它提供类似电子表格的界面，允许开发者交互式地批量编辑 Git 提交的作者、日期和消息，而不直接修改文件内容。 该工具简化了个人开发流程中重写提交历史以满足代码审查需求的繁琐操作，尤其适合在推送前清理工作分支，但受限于签名提交，对注重安全性的工作流影响有限。 Git-knife 通过调用系统 git 命令（如 git commit-tree）重建提交，复用原始树对象以确保文件内容不变；自动在独立命名空间创建备份分支，并使用 git-notes 记录变更。主要局限是无法处理多作者签名的提交历史。

hackernews · YonathanTesfaye · Aug 11, 15:09 · [社区讨论](https://news.ycombinator.com/item?id=49259611)
