## [Datasette 1.0a38 修复 SQL 注入漏洞，防止权限绕过](https://simonwillison.net/2026/Aug/6/datasette/#atom-everything) ⭐️ 9.0/10

Datasette 1.0a38 发布，修复了一个安全漏洞：在混合公有与私有表的数据库中，攻击者可能利用 SQL 注入绕过 execute-sql 权限限制，读取私有表数据。修复同时回溯到 0.65.3 版本。 该漏洞可能导致未授权访问敏感数据，对配置了混合权限的 Datasette 实例构成严重风险。及时升级可防止数据泄露，对数据发布者和管理员至关重要。 该漏洞仅影响在同一数据库内混合配置公有和私有表，并利用 execute-sql 权限控制原始 SQL 查询的场景。漏洞允许通过 SQL 注入以只读方式访问私有表。建议受影响管理员立即升级或暂时禁用 execute-sql 权限。

rss · Simon Willison · Aug 6, 18:24

**背景**: Datasette 是一个用于探索和发布数据的开源工具，允许将数据库发布为交互式网站和 API。其权限系统可控制用户对数据库、表和查询的访问，execute-sql 权限用于管理是否允许用户执行原始 SQL 查询。默认情况下无需认证，但可配置认证和权限来控制访问。

## [提议为 Iceberg Kafka Connect 增加背压控制机制](https://github.com/apache/iceberg/issues/16389) ⭐️ 6.0/10

Apache Iceberg 项目提出新提案（#16389），计划在 Kafka Connect 集成中加入简单的背压控制机制，使 Worker 能够检测 Coordinator 的进度并在必要时暂停自身，以防止 Coordinator 过载时控制消息数量指数增长。 该提案能提升 Iceberg Kafka Connect 在 Coordinator 高负载时的稳定性，避免因控制消息积压导致系统崩溃，对依赖 Kafka 将数据写入 Iceberg 表的数据管道具有重要意义。 Worker 通过主动探测 Coordinator 的进展来判断是否需要暂停，从而限制控制主题消息的无限增长；具体实现方案仍在讨论中，可参见邮件列表。

github · HenryCaiHaiying · Jun 2, 00:01

**背景**: Apache Iceberg 是一种高性能开源表格式，允许多种计算引擎并发安全地访问大型分析表。Kafka Connect 是用于集成 Apache Kafka 与外部系统的框架，其中 Coordinator 负责任务调度，Worker 执行实际的数据同步。在分布式系统中，背压是一种防止下游组件被上游数据淹没的流控机制，此提案正是为了在 Iceberg Kafka Connect 中引入这种机制。

## [提议为 Iceberg REST 目录添加表格和列标签字段](https://github.com/apache/iceberg/issues/15521) ⭐️ 6.0/10

该提案建议在 LoadTableResponse 中增加一个可选的 labels 字段，使目录能够传递表的上下文元数据，如所有权、分类等。 这有助于标准化目录元数据通信，使开源引擎能够消费原本依赖供应商自定义扩展的上下文信息，从而简化跨目录和引擎的集成。 该 labels 字段为可选，将作为 REST 目录规范的一部分。目前 LoadTableResponse 仅返回表格的 schema、快照和文件位置等信息，不包含目录所维护的上下文。

github · laskoviymishka · May 12, 08:00

**背景**: Apache Iceberg 是一种开放式表格格式，其 REST 目录是一种与供应商无关的 HTTP API，用于管理表格元数据。LoadTableResponse 是加载表格时返回的响应对象，目前仅包含表格核心元数据。不同目录（如 AWS Glue、Hive）可能会维护关于表格的额外上下文信息，如所有权、分类和成本归属，但这些信息无法通过标准 Iceberg API 传递。
